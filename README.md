# VM_CTRL Runtime Bundle

This branch contains one stripped QCD runtime bundle for `arm64` on ROS 2 `humble`.

## Target

- Architecture: `arm64`
- ROS 2 distro: `humble`
- Ubuntu: jammy
- Release branch: `release/qcd-arm64-humble`
- Stable target branch: `release/qcd-arm64-humble`
- Release tag format: `qcd0.0.3-arm64-humble`

## Layout

- `build/vm_ctrl` - stripped controller binary
- `run.sh` - runtime launcher
- `Config/` - controller configuration
- `RLController/` - packaged policy configuration and checkpoints
- `lib/` - bundled non-ROS shared libraries
- `third_party/` - bundled runtime dependencies
- `.ros_distro` - required ROS distro metadata

## Host Requirements

This bundle does not ship `ros2_ws` or a ROS 2 overlay because the overlay is target/deployment-owned. By default, `run.sh` uses `../ros2_ws/install/setup.bash` relative to `vm_ctrl`; set `VM_CTRL_ROS2_SETUP` when the trusted overlay lives elsewhere.

Expected runtime layout:

```text
runtime/
├── robots/
├── ros2_ws/              # external/trusted, not shipped in vm_ctrl
│   └── install/
└── vm_ctrl/
    ├── build/
    ├── Config/
    ├── RLController/
    ├── lib/
    ├── third_party/
    └── run.sh
```

Run `vm_ctrl` with the default sibling overlay:

```bash
cd vm_ctrl
./run.sh M2v6 sim
```

Or override the overlay path explicitly:

```bash
VM_CTRL_ROS2_SETUP=/absolute/path/to/ros2_ws/install/setup.bash ./run.sh M2v6 sim
```

## Runtime Guard

- `run.sh` requires ROS 2 `humble`
- launching this bundle with another ROS distro exits immediately
- `run.sh` defaults to `../ros2_ws/install/setup.bash`
- set `VM_CTRL_ROS2_SETUP` to the absolute path of a trusted overlay when not using the default sibling workspace

## ROS 2 Reference

This runtime bundle expects the external ROS 2 overlay to provide the controller interfaces.

Required interface package:

- `vmo_locomotion_interface`
  - messages: `IMUState`, `LowCmd`, `LowState`, `MotorCmd`, `JointCmd`, `JointCmds`, `MotorCmds`, `MotorState`, `JointState`, `JointStates`, `MotorStates`, `FSMState`, `FSMCmd`, `PoseCmd`, `RobotState`, `UpperBodyRequest`, `PacketHeaderState`, `BatteryState`, `BranchState`, `BoardState`
  - actions: `Locomotion`

To inspect the installed interfaces on the target machine:

```bash
source /opt/ros/humble/setup.bash
source ../ros2_ws/install/setup.bash

ros2 interface package vmo_locomotion_interface
ros2 interface show vmo_locomotion_interface/msg/RobotState
ros2 interface show vmo_locomotion_interface/action/Locomotion
```

To inspect the live ROS graph while the controller stack is running:

```bash
source /opt/ros/humble/setup.bash
source ../ros2_ws/install/setup.bash

ros2 node list
ros2 topic list -t
ros2 service list -t
ros2 action list -t
ros2 topic info /<topic_name> --verbose
ros2 interface show <package>/<kind>/<name>
```

That is the authoritative way to get comprehensive publish and subscribe information for the exact release deployed on a machine.
